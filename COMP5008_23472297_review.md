### R02 - Low: distinguish successful vertex insertion from label lookup in the complexity table

**Requirement:** Appendix 1 Section 5 and the complexity-analysis marking criterion.

**Where:** report printed page 6, Table 2, row “Graph label lookup / vertex insertion”; `module1_graph/DSAGraph.py:39-45,54-59`.

The combined row lists best O(1), worst O(V). That is appropriate for label lookup: a matching vertex may be first or last.

For a **successful insertion of a new distinct label**, however, `addVertex()` first calls `hasVertex()`. Establishing that the label is absent scans the entire vertex list. On a graph already containing V vertices, that successful insertion takes Theta(V) for the duplicate check, followed by O(1) linked-list insertion. Finding an existing label immediately is an early duplicate rejection, not a successful new insertion.

**What to do:** separate lookup from successful insertion, or add this qualification to the existing row. The implementation itself need not change. Faster vertex indexing is optional and not required for this assignment.

**Verification:** trace adding a new label to a non-empty graph: `addVertex -> hasVertex -> getVertex -> inspect all existing vertices -> append the new node`.
